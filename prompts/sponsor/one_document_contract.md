# One Sponsor Document Contract

This packet is one document, not a bundle of independent section exports.

Intermediate CSVs are allowed during analysis, but the end product is one readable sponsor memo.

## What the final document must do

- tell one event story from top to bottom
- start with the most decision-relevant findings
- avoid repeating the same number in multiple sections
- use section headers only as structure, not as excuses to restate the same facts

## What each section is responsible for

- `Executive Summary`: sets the primary event story
- `Sponsor Tech Adoption`: explains what was actually used and what usage quality looked like
- `Hiring Insights`: explains who looked strongest and why
- `Sales/BD Insights`: explains where operator/buyer density sits and how it converted
- `Marketing Insights`: explains which stories are externally strong
- `Market Research Insights`: explains audience and project composition only when it sharpens the sponsor read
- `Funnel`: supports the story with conversion context

## Dedupe rules

- If the Executive Summary already states the full funnel, the Funnel section should focus on leak interpretation, not restate every number.
- If Sponsor Tech Adoption already states the top tool pattern, Marketing should only reuse it when needed to explain story value.
- If Market Research gives audience composition, Hiring and Sales/BD should use only the segment comparisons that matter for those goals.

## Sentence standard

Every strong sentence should do three things:

1. state a metric
2. compare or interpret it
3. explain why it matters to the sponsor

## Reject these patterns

- raw stat dumping
- methodology/process narration
- coverage metrics as headline insights
- repeated metrics across multiple sections
- filler recommendations not grounded in the data
